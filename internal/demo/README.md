# Internal demo / acceptance

Fixtures are first-party ASCII text PDFs generated by `make_pdfs.py`. The AI sample
was authored by an AI assistant for this task, not independently annotated detector
evaluation data. The original notes are a first-party example, not a benchmark of
human authorship. Neither is used to invent AI scores or train a production head.

```sh
python -m internal.demo.make_pdfs
python -m internal.demo.run
python -m internal.demo.run --pdf internal/demo/pdfs/ai-sample.pdf
python -m internal.demo.run --live --max-queries 1 --output private/live-report.json
npm run demo
```

Default demo performs genuine PDF extraction, segmentation, lexical comparison and
aggregation against a **controlled retrieval fixture**, not live web search. No AI
mock is used: missing configured model/head gives `unavailable`. `--live` gives
explicit excerpt consent; blocked/empty search is reported, not replaced with
fixtures. Live recall on these first-party examples is not expected.

`npm run demo` uses the built Chrome MV3 extension and the separate local runtime.
It runs real extension APIs, PDF acquisition/parsing, helper authentication, reader,
JSON/text download, consent invalidation, website Unicode/editor exclusion, clear,
multiple embedded PDF selection, navigation invalidation and image-only safe failure.
Its ordinary extension tab emulates side-panel active-tab semantics; a test-only
loopback-origin host pregrant avoids browser-chrome permission prompts. Only source
retrieval is a controlled fixture. AI predictions are not mocked. Outputs are
`screenshots/source-review.png`, `fixture-report.json`, `website-report.txt` and
`browser-validation.json`. Production toolbar permission flows are **not** proven
by this test, nor are detector accuracy and live source recall.

Manual browser acceptance: serve the demo directory with
`python -m http.server 8765 --directory internal/demo`. Open
`http://127.0.0.1:8765/pdfs/source-overlap.pdf`; load the clean Chrome build, pair
its origin, read, consent, scan, inspect tooltips/dual overlap, export, cancel and
navigate to verify invalidation. For embedded detection, use `embedded.html`;
choose the PDF, not the surrounding website. Try `no-text.pdf` and ensure a useful
failure, not a zero-score result. Switch tabs during a scan. Test offline AI only
after licensed model/head provisioning. Firefox native viewer, authenticated and
redirected PDF, complicated reading order, multi-page code and store installation
remain explicit manual gates.
